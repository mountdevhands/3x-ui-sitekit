# 3x-ui SiteKit

[English](README.md) · Русский

SiteKit устанавливает 3x-ui и Xray на отдельный VPS, настраивает nginx,
TLS и VLESS через XHTTP либо WebSocket и создаёт статический сайт с
процедурно сгенерированными материалами.

**Кандидат в релиз: 0.3.0-rc6.** Эта версия объединяет интерактивный мастер,
сохранение QR-кода VLESS и `credentials --refresh-file` в одной поставке.
Команды загрузки рассчитаны на файлы `v0.3.0-rc6`; статус публикации указан
в [GitHub Releases](https://github.com/mountdevhands/3x-ui-sitekit/releases).
Само обновление `main` эти файлы не публикует.

## Требования

- Чистый VPS с Ubuntu 26.04, архитектурой amd64, systemd и системным CPython 3.14.
- Root-доступ для установки и обслуживания.
- Публичный IPv4 непосредственно на интерфейсе VPS; DNS A домена указывает на него.
- Отсутствие AAAA-записи у домена: текущая установка рассчитана на IPv4.
- Свободные TCP 80 и 443, доступные извне; исходящий доступ к DNS, APT и ACME.
- Штатные подписанные репозитории Ubuntu своей серии: release, updates и security.

CDN-прокси и NAT перед VPS не поддерживаются этой сборкой. Для установки
нужен отдельный сервер без действующего nginx, другой панели или существующих
Certbot lineages. `check` не заменяет дополнительные проверки Python,
зависимостей и APT, которые выполняет `install`.


## Одна команда из GitHub Releases

Войдите **на новый сервер под root** через SSH или интерактивную консоль
провайдера. Вставьте блок целиком как одну команду. Для запуска проверенного
мастера RC6 используются системные `curl`, `sha256sum`, `python3` и `ip`.
Домен и email введите в мастере.

<!-- sitekit-release-sha256: setup -->
```bash
(
  set -eu
  sitekit_download=$(mktemp -d)
  trap 'rm -rf -- "$sitekit_download"' EXIT
  curl -q --fail --silent --show-error --location \
    --proto '=https' --proto-redir '=https' \
    --connect-timeout 10 --max-time 60 --retry 2 --retry-max-time 90 \
    --output "$sitekit_download/setup.sh" \
    'https://github.com/mountdevhands/3x-ui-sitekit/releases/download/v0.3.0-rc6/setup.sh'
  printf '%s  %s\n' \
    '75b0917e88793dc10488ea4673ffd7f60940d705f57af822d2f429b0011b2600' "$sitekit_download/setup.sh" |
    sha256sum --check --strict
  bash "$sitekit_download/setup.sh"
)
```
<!-- /sitekit-release-sha256 -->

На первом экране по умолчанию выбран **English**. Там можно выбрать русский
язык. Чтобы сразу открыть русскую версию, добавьте `--lang ru` к последней
строке `bash`. При наличии `whiptail` мастер откроет окна в терминале.
На минимальном образе доступны текстовые меню.
Стрелки выбирают пункт, Tab переключает элементы управления, Enter продолжает
работу. Escape или Cancel закрывают мастер до начала установки.

Мастер устанавливает **rc6**, включая сохранение QR. Он сверяет загрузчик
rc6, а тот проверяет установщик и runtime перед исполнением. Проверенный
runtime побайтно совпадает с комплектом зависимостей rc4. Если в Ubuntu
активен `resolute-backports`, мастер предложит сохранить исходные файлы и
отключить только этот pocket. Затронутые записи видны в итоговой сводке.
[Подробности установки](docs/INSTALL.ru.md).

## Установка с вопросами и ответами

После приветствия мастер проведёт по настройкам:

| Настройка | Что указать или выбрать |
| --- | --- |
| Домен | Свой домен без `https://`, пути и порта. Проверка DNS выполняется сразу. |
| Email для сертификата | Свою почту либо явно подтвердить регистрацию без неё. |
| Доступ к панели | По умолчанию **SSH-туннель**; для обычной ссылки входа выберите **HTTPS через браузер**. |
| Разрешённые IP панели | Необязательное поле в режиме HTTPS. Свой внешний IP/CIDR либо пустое поле — любой IP с обычным логином и паролем панели. |
| Сайт | **Автоматически** выбирает генерируемую тему; можно выбрать конкретную. |
| Транспорт | По умолчанию **XHTTP**, также доступен WebSocket. |

У домена должна быть ровно одна A-запись с публичным IPv4 этого сервера
и не должно быть AAAA. Если DNS не совпал, можно повторить проверку,
изменить домен или отменить установку. После настройки мастер предложит
принять условия Let's Encrypt и подтвердить понятную итоговую сводку.
Оба согласия по умолчанию равны **Нет**. Загрузка файлов установки SiteKit
начнётся только после обоих подтверждений.

Проверенную локальную копию `setup.sh` можно запускать так:

```bash
sudo bash setup.sh --lang en --ui dialog
sudo bash setup.sh --lang ru --ui text
bash setup.sh --lang ru --dry-run
```

По умолчанию выбран `--ui auto`: если доступен `whiptail` и терминал
подходит, используются окна, иначе — нумерованные текстовые меню.
`--ui dialog` требует `whiptail` и подходящий терминал; `--ui text` явно
включает текстовые меню. `--lang en` или `--lang ru` пропускает выбор языка.
EOF, Ctrl-C или отмена завершают работу мастера.

`--dry-run` проверяет DNS и показывает полученную команду, не загружая файлы
релиза и не изменяя систему. Root для него не нужен. Все интерактивные
режимы требуют терминала; для автоматизации используйте
[явные параметры загрузчика](docs/INSTALL.ru.md#установка-с-явными-параметрами).

После установки прочитайте доступы в консоли сервера:

```bash
cat /root/https-node-access.txt
```

При выборе HTTPS откройте точную ссылку **`Public panel:`** и используйте
сохранённые `Username:` и `Password:`. Корень домена открывает созданный сайт.
В режиме SSH воспользуйтесь туннелем и локальным URL из файла доступов.
Пароль, UUID VLESS и случайный путь панели установщик создаёт сам.

## Как открыть админку в браузере без туннеля

При установке по умолчанию включён `ssh`: **публичный адрес панели возвращает
404**. Чтобы включить обычный вход через HTTPS, один раз выполните команду
**в консоли сервера** — через SSH или консоль провайдера:

```bash
sudo python3 /root/https-node.py panel-access \
  --mode https \
  --confirm-domain node.example.com

sudo cat /root/https-node-access.txt
```

Укажите домен своей действующей установки. Пример предполагает, что проверенный
установщик сохранён как `/root/https-node.py`; если файл лежит в другом месте,
используйте его фактический путь. Загрузчик после установки удаляет временную
копию скрипта. Если файла нет, сначала выполните шаг
[получения проверенного установщика](docs/PANEL-ACCESS.ru.md#получить-установщик-для-обслуживания).
Повторно запускать `install` для включения панели не нужно.

Откройте в обычном браузере **точную ссылку из строки `Public panel:`**,
затем введите `Username:` и `Password:` из того же файла. Ссылка содержит
случайный путь вашей установки. Корень домена открывает сайт. После включения
HTTPS можно закрыть SSH: для дальнейших входов туннель не нужен.

Если нужен доступ только со своего внешнего IP:

```bash
sudo python3 /root/https-node.py panel-access \
  --mode https \
  --allow 198.51.100.24/32 \
  --confirm-domain node.example.com
```

Замените учебный адрес `198.51.100.24` своим публичным IP. Для нескольких
адресов или сетей повторите `--allow`. Без него HTTPS доступен с любого IP,
но требует обычный логин и пароль панели. Каждый вызов заменяет список
разрешённых адресов целиком. Ограничения касаются только панели: сайт и VLESS
на том же 443 остаются доступны. SSH также остаётся доступным.

Вернуть доступ только через SSH:

```bash
sudo python3 /root/https-node.py panel-access \
  --mode ssh \
  --confirm-domain node.example.com
```

Для входа в этом режиме запустите туннель **на своём компьютере**, заменив
`SERVER_IP` адресом VPS:

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:2053:127.0.0.1:2053 root@SERVER_IP
```

Не закрывайте процесс туннеля и откройте точный локальный URL
`http://127.0.0.1:2053/.../` из файла доступов в браузере на том же компьютере.
Клиентам VLESS этот административный туннель не нужен.

При каждой чистой установке генерируется свой путь из 32 случайных
hex-символов, например `/9b62d4e1a7304c8fbe09521d6a84f703/`. Текстового
префикса нет; путь не зависит от пароля или домена. Перезагрузка, продление
сертификата и переключение доступа его сохраняют.
[Подробная инструкция](docs/PANEL-ACCESS.ru.md).


## Ссылка и QR-код VLESS

Закрытый файл `/root/https-node-access.txt` содержит адрес панели, логин,
пароль и VLESS-ссылку. **В rc6** установка и переключение режима панели
также сохраняют туда QR-код в обычном UTF-8.
Его нужно сканировать в функции импорта VLESS-клиента; это не вход в админку.
Используйте светлые символы на тёмном фоне и моноширинный шрифт. Расширьте
окно терминала так, чтобы строки QR не переносились, затем сканируйте.

Возьмите [установщик rc6 для обслуживания](docs/PANEL-ACCESS.ru.md#получить-установщик-для-обслуживания)
или соберите соответствующие исходники командой `python3 -B build.py`.
SHA-256 установщика rc6:

<!-- sitekit-release-sha256: installer -->
```text
ad10280e655dad12441f097c97402de73f59fc9ea75eca0b9ccdf35d40dbd8a3
```
<!-- /sitekit-release-sha256 -->

Сверьте скачанный или собранный файл перед использованием как обновлённого
`/root/https-node.py`. С этим установщиком на уже работающем узле:

```bash
sudo python3 /root/https-node.py credentials --refresh-file
sudo cat /root/https-node-access.txt
```

`--refresh-file` обновляет только файл доступов из сохранённого состояния,
оставляя владельца root и права `0600`. Путь панели, пароль, UUID, база,
сайт, сертификат и службы не меняются. При ошибке генерации QR старый файл
остаётся целым. Команда сообщает только путь сохранённого файла.

Чтобы лишь показать доступы и QR без записи файла:

```bash
sudo python3 /root/https-node.py credentials --qr
```

`--refresh-file` входит в rc6. На действующем узле rc4 для этой команды
можно использовать проверенный standalone rc6. QR формируется локально
без ANSI-кодов цвета и отправки VLESS-ссылки стороннему сервису. При ошибке QR во
время установки или изменения режима файл всё равно сохраняет рабочие
доступы и ссылку с явной отметкой о недоступном QR. Ссылка и QR содержат
секрет подключения; храните весь файл приватно.


## Что устанавливается

| Компонент | Назначение |
| --- | --- |
| 3x-ui | Управление пользователями и конфигурацией Xray; слушает loopback |
| Xray | VLESS с XHTTP `auto` или WebSocket за nginx |
| nginx | Публичный сайт, TLS и маршруты транспорта; опционально HTTPS-панель |
| Certbot | Получение и продление сертификата; отдельная среда и systemd timer |
| Генератор сайта | Локальные SVG, CSS, JSON и страницы с описанием созданных материалов |

Команда `install` проверяет SHA-256 runtime и вложенные манифесты до
установки. Управляемые пути и службы используют системное имя `https-node`.


## Установка из готовых файлов

Понадобятся `3x-ui-sitekit-0.3.0-rc6.py` и
`3x-ui-sitekit-0.3.0-rc6-linux-amd64.tar.gz`. Runtime скачивается отдельным
файлом поставки. SHA-256 runtime приведён ниже.

```text
cb2abb5a45b8eee5d30ad0d4e8de6003b088a943ae8f0c2d32af6fec799e787f
```

Сверьте загруженные файлы с доверенной копией `SHA256SUMS`, сохраните
установщик локально как `https-node.py` и подставьте свой домен.

```bash
sudo python3 https-node.py check --domain node.example.com

sudo python3 https-node.py install \
  --domain node.example.com \
  --release-archive ./3x-ui-sitekit-0.3.0-rc6-linux-amd64.tar.gz \
  --transport xhttp \
  --panel-access ssh \
  --site-theme auto \
  --email admin@example.com \
  --agree-tos
```

`--agree-tos` подтверждает согласие с условиями ACME-провайдера. Если
регистрация без почты выбрана осознанно, вместо `--email` можно передать
`--acme-no-email`. Не повторяйте выпуск сертификата циклом при ошибке:
сохраните диагностику и устраните её причину.


## Генерируемый сайт

При установке `auto` выбирает одну из четырёх тем:

| Тема | Создаваемые материалы |
| --- | --- |
| `generative` | Геометрические композиции |
| `patterns` | Бесшовные SVG-тайлы |
| `palettes` | Палитры, CSS-переменные, параметры цветов |
| `curves` | Кривые Безье и контрольные точки |

Страницы описывают параметры реально созданных SVG; CSS и JSON можно
скачать. В JSON включён SHA-256 изображения. Генерация выполняется локально,
без внешнего LLM и API-ключей. Случайный профиль создаётся один раз и
сохраняется; общие пояснения метода между сайтами могут повторяться.
Также доступны прежние явно выбираемые темы; полный список показывает
`preview-site --help`. Собственный статический сайт можно передать
через `--site-dir`.

Локальный предпросмотр не требует root, DNS или сертификата:

```bash
python3 https-node.py preview-site --domain example.test \
  --site-theme palettes --output ./palette-preview

python3 -m http.server 8080 --bind 127.0.0.1 \
  --directory ./palette-preview/site
```

Откройте `http://127.0.0.1:8080/`. Обслуживайте именно подкаталог `site`,
а не соседний приватный `site-profile.json`.


## Обслуживание

```bash
sudo python3 https-node.py status
sudo python3 https-node.py security-check
sudo python3 https-node.py update-nginx --confirm-domain node.example.com
```

`security-check` сверяет выбранные пакеты и закреплённые зависимости с
датированной политикой. `update-nginx` обслуживает пакеты nginx. Для новых
версий 3x-ui, Xray и Certbot требуется проверенная поставка.
[Политика безопасности](SECURITY.ru.md) · [Обновление](docs/UPDATE.ru.md) ·
[Диагностика](docs/DIAGNOSTICS.ru.md) · [Резервные копии](docs/BACKUP.ru.md) ·
[Удаление](docs/UNINSTALL.ru.md).

Состояние находится в `/etc/https-node/state.json`, база панели —
в `/var/lib/https-node/panel/x-ui.db`, сайт — в `/var/www/https-node`.
Перед переносом или удалением сохраняйте приватную согласованную копию
состояния, базы, файлов сайта и данных Certbot. Диагностические checkpoints
не заменяют полную резервную копию. Не публикуйте их вместе с исходниками.


## Сборка и локальные проверки

```bash
python3 -B build.py
sha256sum -c SHA256SUMS.txt
python3 -B -m unittest discover -s tests -p 'test_release_bootstrap.py'
python3 -B tests/test_artifact_sites.py --module dist/https-node.py
```

Полный набор команд приведён в [локальной CI](.github/workflows/ci.yml).
Для проверки маршрутов и ACL на уже имеющемся локальном nginx выполните
команду ниже.

```bash
python3 -B tests/integration_panel_access.py \
  --nginx /absolute/path/to/nginx --module dist/https-node.py
```

Этот тест использует loopback, временный доверенный тестовым клиентом
сертификат и HTTP/WebSocket-заглушки. Он не устанавливает пакеты и не
заменяет приёмку реальных 3x-ui, VLESS и продления сертификата на VPS.


[Отчёт приёмки rc4](docs/ACCEPTANCE-0.3.0-rc4.md) относится к той исторической
поставке. Локальные проверки rc6 не подтверждают новую приёмку VPS, ACME
или перезагрузки. Порядок подготовки и публикации описан в
[RELEASING.md](docs/RELEASING.md).
