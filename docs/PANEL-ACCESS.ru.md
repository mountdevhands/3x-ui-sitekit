# Доступ к панели

[English](PANEL-ACCESS.md) · Русский

## Получить установщик для обслуживания

Загрузчик после установки удаляет свою временную копию Python-скрипта.
Он не создаёт автоматически команду `/root/https-node.py`. Если у вас
ещё нет проверенной rc7 в этом месте, скачайте установщик rc7,
сверьте точный SHA-256 и затем сохраните файл. Ссылка рассчитана на файлы
релиза rc7; статус их публикации указан в
[Releases](https://github.com/mountdevhands/3x-ui-sitekit/releases):

<!-- sitekit-release-sha256: installer -->
```bash
(
  set -eu
  sitekit_download=$(mktemp -d)
  trap 'rm -rf -- "$sitekit_download"' EXIT
  curl -q --fail --silent --show-error --location --proto '=https' \
    --proto-redir '=https' --connect-timeout 10 --max-time 60 --retry 2 \
    --retry-max-time 90 --output "$sitekit_download/https-node.py" \
    'https://github.com/mountdevhands/3x-ui-sitekit/releases/download/v0.3.0-rc7/3x-ui-sitekit-0.3.0-rc7.py'
  printf '%s  %s\n' \
    b6e086aea99af79122210cd79057d3304a31dd1fd02e4976751b852d9cbd55e1 \
    "$sitekit_download/https-node.py" | sha256sum --check --strict
  sudo install -m 0700 "$sitekit_download/https-node.py" /root/https-node.py
)
```
<!-- /sitekit-release-sha256 -->

Standalone rc7 поддерживает `panel-access` и `credentials --refresh-file`.
Загрузка только сохраняет файл управления; обслуживание начинается после
запуска соответствующей команды. Если уже сохранён проверенный установщик
более нового выпуска, используйте его.

## Включить вход через браузер без туннеля

При чистой установке выберите **HTTPS через браузер** в мастере. Команды
ниже переключают режим уже установленного узла.

В режиме по умолчанию `ssh` публичного маршрута панели нет; HTTP 404
по её HTTPS-адресу ожидаем. Один раз в консоли сервера через SSH либо
консоль провайдера выполните:

```bash
sudo python3 /root/https-node.py panel-access \
  --mode https \
  --confirm-domain node.example.com

sudo cat /root/https-node-access.txt
```

Замените домен своим и откройте в обычном браузере точный адрес из строки
`Public panel:`. Введите `Username:` и `Password:` из того же файла.
Корень домена открывает сайт; админка расположена по сохранённому случайному
пути. После включения HTTPS можно закрыть SSH, туннель для дальнейшего
входа не нужен. Файл доступов остаётся закрытым (`root:root`, `0600`).

Для ограничения по IP используйте пример в разделе переключения ниже,
указав собственный публичный адрес вместо учебного. Каждый вызов заменяет
список целиком. Отсутствие `--allow` означает любой IP с обычной авторизацией.

## Адрес и режимы

Новая установка получает один случайный путь `/<32 hex-символа>/`.
Он создаётся вызовом `secrets.token_hex(16)` и сохраняется в приватном
состоянии. Домен задаёт владелец. Повторная чистая установка создаёт новый
путь; обслуживание действующей установки сохраняет прежний, включая пути
старых версий. Путь не заменяет логин и пароль.

По умолчанию `install` использует `--panel-access ssh`: публичного маршрута
панели нет. В режиме `https` nginx проксирует только её точный путь и
вложенные URL на loopback. Backend панели, API Xray и metrics остаются
приватными. Подписочный сервис на порту 2096 не включается.

## Разрешённые адреса

При установке список задаётся повторяемым `--panel-allow`, при переключении —
повторяемым `--allow`. Поддерживаются IP и CIDR; имя хоста вместо адреса
не принимается. CIDR нормализуется к адресу сети. Установка пока IPv4-only;
принимаемый синтаксис IPv6 в списке не включает IPv6-слушатель.

Пустой список в режиме HTTPS разрешает доступ с любого IP, с обычной
авторизацией панели. При наличии списка все остальные источники получают
403, в том числе на URL без завершающего `/`. Ограничение распространяется
на UI, API, статические ресурсы панели и новые WebSocket-подключения.

nginx использует адрес непосредственного TCP-клиента. Присланные
`X-Forwarded-For` и `X-Real-IP` не меняют решение ACL. CDN и другой reverse
proxy перед этим узлом требуют отдельного проектирования доверия к адресам
и не поддерживаются текущей схемой.

Сайт и VLESS используют тот же публичный порт 443, но их маршруты не
получают ACL панели. Ограничение всего 443 в сетевом firewall ограничит
и их. Если внешний IP администратора изменился, исправьте список через SSH.

## Переключение на работающем узле

```bash
sudo python3 https-node.py panel-access \
  --mode https --allow 198.51.100.24/32 \
  --confirm-domain node.example.com

sudo python3 https-node.py panel-access \
  --mode ssh --confirm-domain node.example.com
```

Примеры содержат учебные адреса. Каждый вызов заменяет список целиком.
Команда требует root, точный домен и состояние `ready/complete`.
Она проверяет текущую конфигурацию и сохраняет приватный checkpoint,
затем меняет конфигурацию nginx, состояние и файл доступов.
Путь панели, пароль, UUID, база, сайт и сертификат не пересоздаются.
При ошибке выполняется ограниченный откат; неполное восстановление
возвращает ошибку с расположением checkpoint.

При обнаружении ручных изменений управляемой конфигурации команда
останавливается до их перезаписи. Сначала разберите различия, не удаляйте
состояние установки ради обхода этой проверки. Совпадающий режим и список
не вызывают лишнюю запись файлов или reload.

Сохранение трёх файлов и reload не являются одной атомарной операцией.
Обычные исключения, SIGINT и SIGTERM обрабатываются с откатом. При SIGKILL,
аварии ОС или потере питания требуется проверить checkpoint и фактически
загруженную конфигурацию вручную. Повторный вызов с уже совпадающими файлами
не является проверкой того, какую конфигурацию загрузил работающий nginx.

nginx использует graceful reload. Уже установленные долгоживущие соединения,
в частности WebSocket, могут продолжаться после переключения. Это не
операция немедленного отзыва активных сессий; новые подключения обрабатываются
новой конфигурацией. Для аварийного отзыва доступа требуется отдельное
решение о завершении соединений и смене учётных данных.

## Войти через SSH-туннель

После переключения `--mode ssh` запустите команду на своём компьютере,
заменив `SERVER_IP` адресом VPS:

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:2053:127.0.0.1:2053 root@SERVER_IP
```

Не закрывайте процесс и откройте сохранённый локальный URL вида
`http://127.0.0.1:2053/<ваш-случайный-путь>/` в браузере на том же компьютере.
Используйте логин и пароль из файла доступов. SSH работает также при
включённом HTTPS. Клиенты VLESS импортируют свою ссылку/QR и подключаются
напрямую, административный туннель им не нужен.

## Ссылка и QR-код VLESS

Закрытый файл `/root/https-node-access.txt` содержит адрес панели, логин,
пароль и VLESS-ссылку. **В rc7** установка и переключение режима панели
также сохраняют туда QR-код в обычном UTF-8.
Его нужно сканировать в функции импорта VLESS-клиента; это не вход в админку.
Используйте светлые символы на тёмном фоне и моноширинный шрифт. Расширьте
окно терминала так, чтобы строки QR не переносились, затем сканируйте.

С проверенным установщиком rc7 на уже работающем узле:

```bash
sudo python3 /root/https-node.py credentials --refresh-file
sudo cat /root/https-node-access.txt
```

`--refresh-file` обновляет только файл доступов из сохранённого состояния,
оставляя владельца root и права `0600`. Путь панели, пароль, UUID, база,
сайт, сертификат и службы не меняются. При ошибке генерации QR старый файл
остаётся целым. Команда сообщает только путь сохранённого файла.

Чтобы лишь показать доступы и QR без записи файла:

```bash
sudo python3 /root/https-node.py credentials --qr
```

`--refresh-file` входит в rc7. На существующем узле rc4 для этой команды
нужен проверенный standalone rc7. QR формируется локально без ANSI-кодов
цвета и отправки VLESS-ссылки стороннему сервису. При ошибке QR во
время установки или изменения режима файл всё равно сохраняет рабочие
доступы и ссылку с явной отметкой о недоступном QR. Ссылка и QR содержат
секрет подключения; храните весь файл приватно.

## Проверка после изменения

Проверьте вход с разрешённого адреса и отказ с другого адреса. Для режима
SSH публичный URL должен вернуть 404; вход через локальный SSH-туннель
должен продолжить работать. Убедитесь, что сайт и небольшой запрос через
VLESS сохраняют доступность. Не включайте настоящие URL панели, пароль,
UUID или содержимое файла доступов в публичные отчёты.
