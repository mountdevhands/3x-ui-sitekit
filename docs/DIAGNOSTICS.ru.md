[English](DIAGNOSTICS.md) · Русский

```bash
sudo python3 https-node.py status
sudo python3 https-node.py security-check
sudo systemctl status https-node-panel.service https-node-nginx.service https-node-certbot.timer
sudo journalctl --since today -u https-node-nginx.service -u https-node-panel.service -u https-node-certbot.service
```

На узле RC4 управляемую конфигурацию nginx можно проверить с той же
OpenSSL, которую использует сервис.

```bash
sudo /opt/https-node/nginx-openssl/nginx -t -c /etc/https-node/nginx.conf
```

## Панель не открывается

| Симптом | Что проверить |
| --- | --- |
| На домене открывается сайт | Нужен точный случайный путь панели из закрытого файла доступов |
| Публичная панель возвращает 404 | По умолчанию включён `ssh`; включите `https` по [инструкции](PANEL-ACCESS.ru.md) |
| Панель возвращает 403 | Текущий публичный IP должен входить в список разрешённых адресов панели |
| Не работает локальная ссылка `127.0.0.1:2053` | Откройте SSH-туннель на том же компьютере, где браузер, и не закрывайте процесс |
| `credentials --refresh-file` не распознан | Это параметр версии разработки после rc4; rc4 поддерживает просмотр `credentials --qr` |
| QR из текста не сканируется | Используйте светлые символы на тёмном фоне, моноширинный шрифт и окно без переноса строк; текстовая VLESS-ссылка остаётся пригодной для импорта |

Для DNS и ACME сначала сравните A/AAAA с адресом VPS и доступность TCP 80
из внешней сети. В `status` состояние `failed` сопровождается последней
стадией. Приватные логи Certbot находятся в `/var/log/letsencrypt`.
Для ошибки политики проверьте её срок, версии пакетов и значения
`UNKNOWN`/`BLOCKED`. Перед отправкой вывода уберите учётные данные, URI,
приватные пути и данные production-хоста.

## Установка остановилась на политике источников APT

Опубликованная rc5 может остановиться на стадии `packages` с ошибкой
`APT source suite is outside the reviewed release/security/updates pockets`,
если в образе включён `resolute-backports`. Разрешены только `resolute`,
`resolute-updates` и `resolute-security`. Эта ошибка сообщает о неподдерживаемом
источнике, а не о найденной уязвимости установленного пакета.

При этой конкретной ошибке rc5 проверка источников выполняется до APT update
и установки пакетов самим установщиком. SiteKit уже сохранил состояние
неудачной попытки, но ещё не развернул nginx, панель или Certbot и не запросил
сертификат. Общая подсказка об оставшемся пакете nginx для этого случая неверна.
RC6 проверяет APT на этапе preflight только для чтения и указывает файл
и неподдерживаемый suite. Мастер предлагает точечную правку с резервной копией.

Если попытка установки rc5 уже завершилась ошибкой:

1. Проверьте `status` с помощью проверенного standalone rc5: домен должен
   совпадать, состояние — `failed/packages`. Сохраните `/etc/https-node` в
   резервную копию с доступом только root вне этого каталога. Не публикуйте
   `state.json`: он содержит учётные данные.
2. Убедитесь, что прежняя очистка прошла успешно, runtime ещё не развёрнут,
   служб и выпущенного сертификата нет. Затем
   выполните штатную [команду удаления](UNINSTALL.ru.md) с точным доменом
   неудачной попытки.
3. После сброса запустите мастер RC6. Подтвердите правку backports в мастере
   или передайте `--disable-apt-backports` явной команде установки.

Если ошибка возникла позже и файлы nginx уже присутствуют, его штатная служба
должна быть остановлена и отключена, а ручному установщику потребуется
`--reuse-stock-nginx`. Не применяйте такое восстановление к работающему узлу.
