# Чистая установка

[English](INSTALL.md) · Русский

Команды в этой ревизии рассчитаны на **v0.3.0-rc6**. Используйте её
опубликованные файлы из [GitHub Releases](https://github.com/mountdevhands/3x-ui-sitekit/releases):
коммит исходников и публикация релиза выполняются отдельно.

Нужны Ubuntu 26.04 amd64, системный CPython 3.14, systemd, свободные TCP
80/443 и публичный IPv4 на интерфейсе VPS. Направьте одну A-запись домена
на этот IPv4 и удалите AAAA. Эта поставка не настраивает IPv6-слушатель;
CDN-прокси и NAT перед VPS не поддерживаются.

Используйте штатные подписанные Ubuntu pockets `resolute`,
`resolute-updates` и `resolute-security` с дистрибутивным `Signed-By`.
Мастер заранее обнаруживает `resolute-backports` и показывает предлагаемое
изменение в итоговом подтверждении. При явной установке это изменение
разрешает параметр `--disable-apt-backports`.

Установщик проверяет политику APT до записи состояния и маскирования nginx.
После подтверждения он сохраняет файлы в приватном каталоге
`/root/sitekit-apt-backports.*` и отключает только backports. Если правка или
повторная проверка доверия завершается ошибкой, установщик возвращает оригиналы.
Команды `check` и `--dry-run` только читают источники. Для прежнего сбоя RC5
см. [восстановление после ошибки APT](DIAGNOSTICS.ru.md#установка-остановилась-на-политике-источников-apt).

Нужен отдельный чистый хост со свободными портами, без прежнего состояния
SiteKit и Certbot lineage. В интерактивной консоли под root запустите
[мастер одной командой](../README.ru.md#одна-команда-из-github-releases).
Для запуска нужны `curl`, `sha256sum`, `python3` и `ip`. При наличии `whiptail`
мастер использует окна, в остальных случаях открывает текстовые меню.

## Установка с вопросами и ответами

После приветствия мастер проведёт по настройкам:

| Настройка | Что указать или выбрать |
| --- | --- |
| Домен | Свой домен без `https://`, пути и порта. Проверка DNS выполняется сразу. |
| Email для сертификата | Свою почту либо явно подтвердить регистрацию без неё. |
| Доступ к панели | По умолчанию **SSH-туннель**; для обычной ссылки входа выберите **HTTPS через браузер**. |
| Разрешённые IP панели | Необязательное поле в режиме HTTPS. Свой внешний IP/CIDR либо пустое поле — любой IP с обычным логином и паролем панели. |
| Сайт | **Автоматически** выбирает генерируемую тему; можно выбрать конкретную. |
| Транспорт | По умолчанию **XHTTP**, также доступен WebSocket. |

У домена должна быть ровно одна A-запись с публичным IPv4 этого сервера
и не должно быть AAAA. Если DNS не совпал, можно повторить проверку,
изменить домен или отменить установку. После настройки мастер предложит
принять условия Let's Encrypt и подтвердить понятную итоговую сводку.
Оба согласия по умолчанию равны **Нет**. Загрузка файлов установки SiteKit
начнётся только после обоих подтверждений.

Проверенную локальную копию `setup.sh` можно запускать так:

```bash
sudo bash setup.sh --lang en --ui dialog
sudo bash setup.sh --lang ru --ui text
bash setup.sh --lang ru --dry-run
```

По умолчанию выбран `--ui auto`: если доступен `whiptail` и терминал
подходит, используются окна, иначе — нумерованные текстовые меню.
`--ui dialog` требует `whiptail` и подходящий терминал; `--ui text` явно
включает текстовые меню. `--lang en` или `--lang ru` пропускает выбор языка.
EOF, Ctrl-C или отмена завершают работу мастера.

`--dry-run` проверяет DNS и показывает полученную команду, не загружая файлы
релиза и не изменяя систему. Root для него не нужен. Все интерактивные
режимы требуют терминала; для автоматизации используйте
[явные параметры загрузчика](#установка-с-явными-параметрами).

После установки прочитайте доступы в консоли сервера:

```bash
cat /root/https-node-access.txt
```

При выборе HTTPS откройте точную ссылку **`Public panel:`** и используйте
сохранённые `Username:` и `Password:`. Корень домена открывает созданный сайт.
В режиме SSH воспользуйтесь туннелем и локальным URL из файла доступов.
Пароль, UUID VLESS и случайный путь панели установщик создаёт сам.


## Установка с явными параметрами

Для автоматизации загрузите закреплённый bootstrap rc6, проверьте SHA-256
и передайте настройки явно. В этом примере нужны `curl`, `sha256sum` и
`sudo`; при работе под root можно убрать `sudo`. Подставьте свой домен
и email. Передавайте `--agree-tos` после согласия с условиями ACME-провайдера.

<!-- sitekit-release-sha256: bootstrap -->
```bash
(
  set -eu
  sitekit_download=$(mktemp -d)
  trap 'rm -rf -- "$sitekit_download"' EXIT
  curl -q --fail --silent --show-error --location \
    --proto '=https' --proto-redir '=https' \
    --connect-timeout 10 --max-time 60 --retry 2 --retry-max-time 90 \
    --output "$sitekit_download/install.sh" \
    'https://github.com/mountdevhands/3x-ui-sitekit/releases/download/v0.3.0-rc6/install.sh'
  printf '%s  %s\n' \
    '9b08fbc3655573fc9a124d31f844bc8c307dbf71177e0b7f8042d0b359e4e209' "$sitekit_download/install.sh" |
    sha256sum --check --strict
  sudo bash "$sitekit_download/install.sh" \
    --repository mountdevhands/3x-ui-sitekit \
    --domain node.example.com --email admin@example.com --agree-tos \
    --panel-access ssh --site-theme auto --transport xhttp
)
```
<!-- /sitekit-release-sha256 -->

Для регистрации без почты вместо `--email` явно передайте `--acme-no-email`.
`--transport` принимает `xhttp` или `ws`. Загрузчик передаёт проверенный
локальный runtime через `--release-archive`. Если файлы уже на сервере,
используйте [установку из готовых файлов](../README.ru.md#установка-из-готовых-файлов).

## Выбор доступа к панели

В мастере есть меню **SSH-туннель** / **HTTPS через браузер**. По умолчанию
выбран SSH. При запуске загрузчика с аргументами для HTTPS укажите
`--panel-access https`; при необходимости повторите
`--panel-allow ВАШ_ПУБЛИЧНЫЙ_IP/32` для каждого клиентского адреса или CIDR.

Указывайте публичный адрес своего компьютера, а не IP сервера. Пустой список
разрешает любой IP с обычным логином и паролем панели. Правила касаются
только панели; сайт и VLESS остаются доступны. Режим можно изменить позднее
командой [`panel-access`](PANEL-ACCESS.ru.md), сохранив сертификат и путь панели.

## Завершение и обслуживание

После успеха прочитайте `/root/https-node-access.txt` на сервере под root.
Там находятся URL панели, логин, пароль, VLESS-ссылка и в rc6 её QR в UTF-8.
Откройте нужный URL по [инструкции доступа](PANEL-ACCESS.ru.md).
Сохраните проверенный standalone как `/root/https-node.py` для обслуживания:
bootstrap удаляет временный скачанный установщик. При отсутствии файла
используйте [загрузку с проверкой SHA-256](PANEL-ACCESS.ru.md#получить-установщик-для-обслуживания).

При ошибке сохраните вывод и проверьте стадию перед новым запросом к ACME.
Для действующего готового узла используйте команды обслуживания.
`--dry-run` проверяет настройки, но не заменяет настоящую установку
и приёмку сертификата.
