# Доступ к панели

## Адрес и режимы

Новая установка получает один случайный путь `/<32 hex-символа>/`.
Он создаётся вызовом `secrets.token_hex(16)` и сохраняется в приватном
состоянии. Домен задаёт владелец. Повторная чистая установка создаёт новый
путь; обслуживание действующей установки сохраняет прежний, включая пути
старых версий. Путь не заменяет логин и пароль.

По умолчанию `install` использует `--panel-access ssh`: публичного маршрута
панели нет. В режиме `https` nginx проксирует только её точный путь и
вложенные URL на loopback. Backend панели, API Xray и metrics остаются
приватными. Подписочный сервис на порту 2096 не включается.

## Разрешённые адреса

При установке список задаётся повторяемым `--panel-allow`, при переключении —
повторяемым `--allow`. Поддерживаются IP и CIDR; имя хоста вместо адреса
не принимается. CIDR нормализуется к адресу сети. Установка пока IPv4-only;
принимаемый синтаксис IPv6 в списке не включает IPv6-слушатель.

Пустой список в режиме HTTPS разрешает доступ с любого IP, с обычной
авторизацией панели. При наличии списка все остальные источники получают
403, в том числе на URL без завершающего `/`. Ограничение распространяется
на UI, API, статические ресурсы панели и новые WebSocket-подключения.

nginx использует адрес непосредственного TCP-клиента. Присланные
`X-Forwarded-For` и `X-Real-IP` не меняют решение ACL. CDN и другой reverse
proxy перед этим узлом требуют отдельного проектирования доверия к адресам
и не поддерживаются текущей схемой.

Сайт и VLESS используют тот же публичный порт 443, но их маршруты не
получают ACL панели. Ограничение всего 443 в сетевом firewall ограничит
и их. Если внешний IP администратора изменился, исправьте список через SSH.

## Переключение на работающем узле

```bash
sudo python3 https-node.py panel-access \
  --mode https --allow 198.51.100.24/32 \
  --confirm-domain node.example.com

sudo python3 https-node.py panel-access \
  --mode ssh --confirm-domain node.example.com
```

Примеры содержат учебные адреса. Каждый вызов заменяет список целиком.
Команда требует root, точный домен и состояние `ready/complete`.
Она проверяет текущую конфигурацию и сохраняет приватный checkpoint,
затем меняет конфигурацию nginx, состояние и файл доступов.
Путь панели, пароль, UUID, база, сайт и сертификат не пересоздаются.
При ошибке выполняется ограниченный откат; неполное восстановление
возвращает ошибку с расположением checkpoint.

При обнаружении ручных изменений управляемой конфигурации команда
останавливается до их перезаписи. Сначала разберите различия, не удаляйте
состояние установки ради обхода этой проверки. Совпадающий режим и список
не вызывают лишнюю запись файлов или reload.

Сохранение трёх файлов и reload не являются одной атомарной операцией.
Обычные исключения, SIGINT и SIGTERM обрабатываются с откатом. При SIGKILL,
аварии ОС или потере питания требуется проверить checkpoint и фактически
загруженную конфигурацию вручную. Повторный вызов с уже совпадающими файлами
не является проверкой того, какую конфигурацию загрузил работающий nginx.

nginx использует graceful reload. Уже установленные долгоживущие соединения,
в частности WebSocket, могут продолжаться после переключения. Это не
операция немедленного отзыва активных сессий; новые подключения обрабатываются
новой конфигурацией. Для аварийного отзыва доступа требуется отдельное
решение о завершении соединений и смене учётных данных.

## Проверка после изменения

Проверьте вход с разрешённого адреса и отказ с другого адреса. Для режима
SSH публичный URL должен вернуть 404; вход через локальный SSH-туннель
должен продолжить работать. Убедитесь, что сайт и небольшой запрос через
VLESS сохраняют доступность. Не включайте настоящие URL панели, пароль,
UUID или содержимое файла доступов в публичные отчёты.
